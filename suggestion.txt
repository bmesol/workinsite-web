SECTION 2 — RECOMMENDED APPROACH
────────────────────────────────────────────────────────────────────────────────

Use the W3C Contact Picker API (navigator.contacts.select).

Why:
  - Zero backend dependencies, no OAuth, no file parsing.
  - Native OS picker on Android — same UX the mobile app already provides.
  - Falls back gracefully: the button simply does not render on unsupported
    browsers/devices, so desktop users are unaffected.

Key facts about the Contact Picker API:
  - Supported: Android Chrome 80+ (Chromium-based browsers on Android).
  - NOT supported: iOS Safari (Apple has not implemented it as of 2025).
  - NOT supported: Any desktop browser (Chrome, Firefox, Edge, Safari on macOS/
    Windows/Linux all return undefined for navigator.contacts).
  - HTTPS required: The API throws SecurityError on http:// origins.
    The WorkInSite web app must be served over HTTPS in production (which it
    presumably already is). Works on localhost for dev (localhost is secure).
  - User-gesture required: navigator.contacts.select() must be called from
    inside a click/touch handler. Calling it programmatically without a gesture
    will throw.
  - Permission model: Android shows its own native picker — the browser does NOT
    show a separate "Allow contacts" prompt. The user grants access by selecting
    contacts inside the picker itself.

Feature detection (the only reliable method):
  const isSupported = 'contacts' in navigator && 'ContactsManager' in window;

This single check covers all the edge cases:
  - false on all desktop browsers
  - false on iOS Safari
  - false on non-HTTPS pages (ContactsManager won't be defined)
  - true only on Android Chrome 80+

Core principle: the "Select Contact" button and the "OR" divider are rendered
ONLY when isSupported === true. Otherwise the page looks exactly as it does
today — two plain input fields. No empty space, no disabled buttons.

SECTION 3 — HOOK DESIGN AND CODE SNIPPET
────────────────────────────────────────────────────────────────────────────────

File to create:
  src/shared/hooks/useContactPicker.ts

Purpose:
  Wraps navigator.contacts.select into a reusable hook that:
    1. Detects support.
    2. Opens the OS contact picker on user tap.
    3. Extracts the first name and first phone number from the selected contact.
    4. Normalizes the phone number to the last 10 digits (mirrors mobile
       formatPhone behaviour).
    5. Returns the result so the caller can populate setName/setPhone.
    6. Handles user cancellation (user dismisses picker without selecting).
    7. Handles empty or missing fields gracefully.

--- HOOK CODE SNIPPET ---

// src/shared/hooks/useContactPicker.ts

// TypeScript declarations for the Contact Picker API (not yet in lib.dom.d.ts
// for all TS versions).
interface ContactAddress {
  city?: string;
  country?: string;
  postalCode?: string;
  streetAddress?: string;
}

interface ContactInfo {
  name: string[];
  tel: string[];
  email: string[];
  address: ContactAddress[];
  icon: Blob[];
}

interface ContactsManager {
  select(
    properties: Array<keyof ContactInfo>,
    options?: { multiple?: boolean }
  ): Promise<ContactInfo[]>;
  getProperties(): Promise<Array<keyof ContactInfo>>;
}

declare global {
  interface Navigator {
    contacts?: ContactsManager;
  }
  interface Window {
    ContactsManager?: unknown;
  }
}

// ─── helpers ─────────────────────────────────────────────────────────────────

/**
 * Strip all non-digit characters then take the last 10 digits.
 * Mirrors the mobile app's formatPhone utility.
 *
 * Examples:
 *   "+91 98765 43210"  → "9876543210"
 *   "98765 43210"      → "9876543210"
 *   "043-12345678"     → "1234567800"  (only 10 of 10 kept — real data edge)
 *   "12345"            → "12345"       (shorter than 10 — caller validates)
 */
const formatPhone = (raw: string): string => {
  const digits = raw.replace(/\D/g, "");
  return digits.length > 10 ? digits.slice(-10) : digits;
};

// ─── result type ─────────────────────────────────────────────────────────────

export type ContactPickerResult = {
  name: string;
  phone: string;
};

export type PickContactFn = () => Promise<ContactPickerResult | null>;

export type UseContactPickerReturn = {
  isSupported: boolean;
  pickContact: PickContactFn;
};

// ─── hook ────────────────────────────────────────────────────────────────────

export const useContactPicker = (): UseContactPickerReturn => {
  const isSupported =
    typeof navigator !== "undefined" &&
    "contacts" in navigator &&
    "ContactsManager" in window;

  const pickContact: PickContactFn = async () => {
    if (!isSupported || !navigator.contacts) return null;

    try {
      const results = await navigator.contacts.select(["name", "tel"], {
        multiple: false,
      });

      // User closed picker without selecting
      if (!results || results.length === 0) return null;

      const contact = results[0];

      // Extract name — contacts.name is an array; take first non-empty entry
      const rawName = contact.name?.find((n) => n.trim().length > 0) ?? "";

      // Extract phone — contacts.tel is an array
      const tels = contact.tel ?? [];

      if (tels.length === 0) {
        // Contact has no phone number stored
        return { name: rawName, phone: "" };
      }

      // Single phone: use it directly.
      // Multiple phones: take the first one.
      // (See Section 6 for the multi-phone UX upgrade path.)
      const rawPhone = tels[0];
      const phone = formatPhone(rawPhone);

      return { name: rawName, phone };
    } catch (err: unknown) {
      // AbortError — user cancelled the picker
      if (err instanceof DOMException && err.name === "AbortError") {
        return null;
      }
      // SecurityError — non-HTTPS or picker already open
      if (err instanceof DOMException && err.name === "SecurityError") {
        console.warn("useContactPicker: requires HTTPS", err);
        return null;
      }
      // Unexpected error — rethrow so the caller can decide
      throw err;
    }
  };

  return { isSupported, pickContact };
};

--- END HOOK CODE SNIPPET ---

Notes on the design:
  - isSupported is evaluated at render time (not inside an effect) because the
    DOM APIs are synchronously available; no async check is needed.
  - multiple: false matches the mobile UX (one contact at a time).
  - The hook returns null (not an error) on cancellation, so the caller does not
    need a try/catch — just a null check.
  - formatPhone here is a local utility, identical to the mobile version.
    If the project later adds a shared utils file, move it there.

Multi-phone upgrade path (optional, rated low effort / medium value):
  If tels.length > 1, instead of always taking tels[0], you could return all
  cleaned numbers and let the UI show a small inline selection (radio buttons or
  a dropdown). This is not required for the first version — most contacts have
  one primary phone, and the first number is typically the most-used one.

Behaviour summary:
  - Android Chrome: shows the "Select from Contacts" button → user taps → OS
    picker opens → user selects → name and phone are pre-filled → user can edit
    before saving.

    fills Name and Phone manually (unchanged experience).
  - If the selected contact has no phone number, phone field is left empty and
    the user fills it in manually (validation will catch it on submit).
  - If the selected contact's phone has more than 10 digits (e.g. +91 prefix),
    formatPhone trims to the last 10 digits automatically.
